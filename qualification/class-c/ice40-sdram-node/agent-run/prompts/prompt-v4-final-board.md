Class C case 2, FPGA package change: ice40_sdram_node on a 144-pin TQFP iCE40 (Synth MCP only)

Your workspace holds ice40_sdram_node.synth (an iCE40HX4K FPGA with an IS42S16400J SDR SDRAM, an SPI boot flash, a USB-C power input and a 1x6 programming header, six layers, declared net classes, length-match groups and budgets). Work only through the Synth MCP tools and Read/Write/Edit limited to this workspace; do not invent part numbers, datasheet values or tool results; never edit exported KiCad files.

Why the change: with the 121-ball BGA (0.8 mm pitch, 0.46 mm in-pad vias) no ground return via fits beside the SDRAM bus vias, and Synth blocks release without one (W-SYNTH-DRC-016). A leaded package leaves room, so U3 becomes the 144-pin TQFP part.

Do this in the Synth source:
1. Replace U3's part with the user-registry part `ice40hx4k_tq144` (Lattice iCE40HX4K-TQ144, KiCad symbol FPGA_Lattice:ICE40HX4K-TQ144, footprint Package_QFP:TQFP-144_20x20mm_P0.5mm). Read its pin map in user-registry/ice40hx4k_tq144.synth.toml: pins are named by their bank and pad (for example iol_2a, iob_108_ss), numbered 1 to 144, numbering counter-clockwise from the top-left corner (pins 1 to 36 on the left side, 37 to 72 on the bottom, 73 to 108 on the right, 109 to 144 on the top). Remove the BGA-only declarations: `escape { method underpad }` on U3 (declare `escape { off }` on U3, a leaded package), and drop `requires via_in_pad` and the via-in-pad process if nothing else needs them; keep the six-layer stackup and the manufacturer profile that still fit.
2. Reconnect every U3 net to a pin of the new part. Keep the fixed functions: SPI_SS_B, SPI_SCK, SPI_SDI, SPI_SDO to the pins named iob_108_ss, iob_107_sck, iob_106_sdi, iob_105_sdo; CRESET_B to creset; CDONE to cdone; the PLL supplies on vccpll0/vccpll1 with gndpll0/gndpll1; every vccio_* and vcc pad and every gnd pad connected to the right rail (all the duplicated gnd, vcc and vccio pads of the part are real pads and must be connected); vcc_spi to the 3.3 V rail; vpp_2v5 to 2.5 V? Read the part and the Lattice datasheet statements in its description and decide, state the arithmetic, and if a pin needs a rail the board lacks say so plainly instead of inventing one. vpp_fast is left unconnected; the nc pins stay unconnected.
3. Assign the SDRAM bus (SD_DQ0..15, SD_A0..11, SD_BA0, SD_BA1, SD_CS, SD_RAS, SD_CAS, SD_WE, SD_CKE, SD_CK, SD_UDQM, SD_LDQM and the series-resistor sides) to I/O pins on the side of the FPGA that faces the SDRAM, adjacent pins in bus order so the bus routes without crossings; keep the clock on a global-buffer pad (gbin) if the part marks one. Keep every net class, length-match group and budget.
4. Placement: FPGA near the middle, the SDRAM beside it on the side that holds the SDRAM bus pins, the series resistors at the FPGA end, each decoupling capacitor at its pin, the USB-C flush on an edge with its opening facing out, the programming header on an edge near the FPGA and the flash, mounting holes at opposite corners. Write a placement sidecar and aim for a courtyard fill of at least 30 percent; remove optional parts (test points, indicator LEDs) only if the board cannot otherwise be placed and routed, and say which.
5. Run validate and the placement review (synth_place_with_hints, run_routing=false) and fix what it names. Then STOP. Do NOT call synth_export or any routing. Write REPORT.md with the pin assignment table (net, pin number, pin name), the part identities and the placement review result.
